Файл:

* watchdog observer
* worker threads
* очередей обработки
Требования:
1. Найти все точки завершения демона.
2. Обеспечить гарантированный вызов _shutdown().
3. Исключить двойной вызов _shutdown().
4. Корректно обрабатывать исключения.
5. Не изменять бизнес-логику проекта.
6. Не изменять структуру БД.
7. Не изменять web-интерфейс.
Результат:
Предоставить:
* анализ проблемы;

* краткое объяснение изменений.

PROMPT 02
Устранение полной загрузки письма в память
Проект: mail-proxy
Файл:
mail-proxy-daemon.py
Проблема:
Сейчас письмо перед отправкой полностью загружается в память.
При вложениях 100–150 МБ и сотнях одновременно работающих референтов это приводит к чрезмерному потреблению RAM.
Важно:
Проект использует внешние SMTP серверы клиентов.
Поддерживаются:
* SMTP AUTH
* OAuth2 XOAUTH2
Запрещено:
* заменять внешнюю SMTP отправку на локальный sendmail;
* удалять поддержку OAuth2.
Требования:
1. Устранить полную загрузку письма в память.
2. Сохранить поддержку:
o SMTP AUTH
o XOAUTH2
3. Использовать потоковую передачу данных.
4. Минимизировать потребление памяти.
5. Не менять бизнес-логику.
Допустимо:
* чтение файла чанками;
* временные файлы;
* потоковая передача через smtplib.
Результат:
Предоставить:
* техническое решение;
* unified diff patch;
* оценку потребления памяти до и после изменений.
