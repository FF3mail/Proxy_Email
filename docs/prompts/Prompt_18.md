Проведи локальное исправление дефекта безопасности.

Контекст:

При редактировании внешнего аккаунта используются запросы вида:

SELECT ... WHERE id = ?

и

UPDATE ... WHERE id = ?

Проверка принадлежности аккаунта текущему referent отсутствует.

Требуется устранить возможность изменения чужого аккаунта через подмену идентификатора.

ЖЁСТКИЕ ОГРАНИЧЕНИЯ:

1. НЕ менять архитектуру проекта.
2. НЕ менять схему БД.
3. НЕ создавать новые таблицы.
4. НЕ менять модель авторизации.
5. НЕ менять маршрутизацию.
6. НЕ вводить RBAC.
7. НЕ создавать новые сервисы.
8. НЕ выполнять рефакторинг.
9. НЕ менять интерфейсы функций.
10. Если потребуется архитектурное изменение — остановиться.

Требуемое поведение:

- все SELECT аккаунта должны проверять:
  account_id + referent_id

- все UPDATE аккаунта должны проверять:
  account_id + referent_id

- при отсутствии доступа возвращать существующую ошибку доступа либо ближайший существующий механизм

Формат ответа:

1. Причина уязвимости.
2. Минимальный patch.
3. Возможные побочные эффекты.
4. Регрессионные тесты.

Запрещено изменять модель авторизации проекта.
