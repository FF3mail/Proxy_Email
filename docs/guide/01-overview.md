# 1. Обзор системы DELTA-transit

## 1.1. Задача, которую решает система

В организации у сотрудников часто есть **корпоративный ящик** (на сервере iRedMail) и **внешний ящик** (Gmail, Yandex, Outlook и т.д.). DELTA-transit связывает их через роль **референта**:

- **Входящая почта:** демон опрашивает внешний IMAP и доставляет письма в локальный ящик референта через Postfix (порт 25).
- **Исходящая почта:** демон следит за папкой исходящих (Maildir) и отправляет письма через внешний SMTP.

Референт — это не «ещё один пользователь Linux», а **логическая связка** в базе данных: локальный inbox/outbox + внешний аккаунт + клиентский email.

### Зачем это нужно администратору

Без DELTA-transit сотрудник вручную копирует почту или настраивает клиент на два аккаунта. С прокси почта **централизованно** проходит через ваш сервер: проще аудит, единая точка резервного копирования Maildir и контроль политик.

---

## 1.2. Основные компоненты

| Компонент | Технология | Роль |
|-----------|------------|------|
| Демон | Python 3 (`mail-proxy-daemon.py`) | Опрос IMAP, отправка SMTP, OAuth2, watchdog Maildir |
| Веб-панель | PHP + Nginx + PHP-FPM | Настройка референтов, аккаунтов, OAuth-провайдеров |
| База данных | MariaDB (`mail_proxy`) | Конфигурация, зашифрованные пароли и токены |
| Локальная почта | Postfix + Dovecot | Приём и хранение Maildir |
| Управление | systemd (`mail-proxy.service`) | Автозапуск, hardening, лимиты ресурсов |

Демон работает от пользователя **`vmail`** — того же, что использует Dovecot для доставки почты. Это важно: демон должен иметь право писать в Maildir и читать исходящие.

---

## 1.3. Схема потоков данных

```
ВХОДЯЩАЯ ПОЧТА
  Внешний IMAP (Gmail/Yandex/…)
       │
       ▼  опрос каждые ~60 с
  mail-proxy-daemon (ImapPoller → очередь → 20 воркеров)
       │
       ▼  SMTP localhost:25
  Postfix → Dovecot → Maildir референта (local_inbox)

ИСХОДЯЩАЯ ПОЧТА
  Пользователь кладёт письмо в local_outbox (Maildir)
       │
       ▼  watchdog (inotify)
  mail-proxy-daemon (очередь → 20 SMTP-воркеров)
       │
       ▼  внешний SMTP (TLS)
  Интернет
```

**Комментарий:** очереди внутри демона — это потоки в памяти (до 5000 задач IMAP и 1000 SMTP), а не таблица в MariaDB. В старых черновиках документации могла фигурировать таблица `mail_queue` — в текущей схеме её **нет**.

## 1.4. Ключевые каталоги на сервере

| Путь | Назначение |
|------|------------|
| `/opt/delta-transit/venv/` | Виртуальное окружение Python (зависимости демона) |
| `/usr/local/bin/mail-proxy-daemon.py` | Установленный демон |
| `/etc/mail-proxy/crypto.key` | Ключ AES-256 для паролей и токенов |
| `/etc/mail-proxy/db.conf` | Подключение к MariaDB (секция `[db]`) |
| `/var/log/mail-proxy/` | Логи демона и веб-панели |
| `/var/spool/mail-proxy/tmp/` | Временные `.eml` при передаче больших писем |
| `/var/www/mail-proxy/` | Файлы веб-панели |
| `/var/vmail/` | Хранилище Maildir (типично iRedMail) |

---

## 1.5. Пользователи и группы Linux

| Субъект | Зачем |
|---------|-------|
| `vmail` | Запуск демона, доступ к Maildir и временным файлам |
| `www-data` | PHP-FPM веб-панели |
| `mail-proxy-crypto` | Группа для чтения `crypto.key` и `db.conf` (`vmail` + `www-data`) |
| `mail-proxy-logs` | Группа для чтения логов (`www-data` видит логи, но **не** Maildir) |

> **Важно:** `www-data` **не** должен входить в группу `vmail`. Инсталлятор явно удаляет такое членство — это защита от утечки почты через веб-сервер.

---

## 1.6. Веб-панель и доступ

Доступ к панели — **два слоя**:

1. **Сетевой allow-list** (`checkLocalNetworkAccess()`): разрешены только IP из частных сетей (10.x, 172.16–31.x, 192.168.x) и localhost; вне диапазона — **403** без формы входа.
2. **Учётные записи операторов** в таблице `panel_admins` (MariaDB): после прохождения allow-list требуется логин и пароль. Один **master** (seed при установке) и дополнительные **admin** (создаёт master).

**Практический смысл:** панель предназначена для администрирования **из корпоративной сети или через VPN/SSH-туннель**. Allow-list **не заменяет** аутентификацию — даже из LAN нужен пароль оператора. Подробности — [05-web-panel.md](05-web-panel.md) §5.2 и [08-security.md](08-security.md) §8.5.

## 1.7. Аутентификация внешних ящиков

Поддерживаются два типа (`auth_type` в БД):

| Тип | Когда использовать |
|-----|-------------------|
| `plain` | Логин и пароль IMAP/SMTP (пароль хранится зашифрованным) |
| `oauth2` | Google, Yandex, Microsoft — через преднастроенных провайдеров |

Для OAuth2 в `config.php` задаётся **`APP_BASE_URL`** — публичный HTTPS-URL панели. Он должен **отличаться** от hostname Postfix (`myhostname`), например: Postfix `mail.example.com`, панель `https://panel.example.com`.

---

## 1.8. Лимиты на размер вложений

Целевой размер вложения: **150 МБ**. С учётом Base64 при SMTP фактический лимит сообщения ~**200 МБ**. Согласованные значения задаются скриптом `configure_limits.sh` в Postfix, Nginx, PHP и MariaDB. Подробности — в [04-configuration.md](04-configuration.md).

Демон дополнительно проверяет размер **до** загрузки письма с IMAP (`RFC822.SIZE`), чтобы не исчерпать RAM на гигантских сообщениях.
